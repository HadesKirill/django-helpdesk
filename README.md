# HelpDesk

Проект для собеседования:
сервис заявок на обслуживание оборудования.

Заказчик регистрирует проблему, исполнитель выполняет работу,
заказчик подтверждает результат. Участники обсуждают заявку
в комментариях, изменения статусов сохраняются в истории.

## Стек

- Python 3.13
- Django 5.2
- SQLite для локальной разработки
- Django Templates, HTML, CSS
- Django TestCase
- GitHub Actions

Точные версии зависимостей находятся в requirements.txt.

## Возможности

- Вход и выход из системы.
- Роли заказчика и исполнителя.
- Управление пользователями и оборудованием через Django Admin.
- Создание заявок и просмотр подробностей.
- Ограничение доступа к заявкам по роли и участию.
- Последовательная смена статусов.
- История изменений с автором и временем.
- Комментарии участников.
- Поиск, фильтры и постраничный вывод.
- Сводка по доступным заявкам и контроль текущей просрочки.

## Правила доступа

| Пользователь | Доступ         |
|--------------|----------------|
| Гость        | Страница входа |
| Заказчик     | Создание и просмотр своих заявок |
| Исполнитель  | Просмотр назначенных ему заявок |
| Суперпользователь | Просмотр всех заявок и администрирование |

Создание заявки через пользовательскую форму доступно роли
«Заказчик». Автор определяется на сервере из текущей сессии.

## Жизненный цикл заявки

| Переход | Кто выполняет |
|---|---|
| Новая → В работе | Назначенный исполнитель |
| В работе → Выполнена | Назначенный исполнитель |
| Выполнена → Закрыта | Заказчик заявки |

Суперпользователь может выполнять эти же переходы.
Для начала работы необходимо назначить исполнителя.
Пропуск этапов и повторное открытие закрытой заявки не предусмотрены.

Смена статуса и запись истории выполняются в одной транзакции.
Комментарии доступны участникам и после закрытия заявки.

Просроченной считается заявка с истёкшим сроком выполнения
в статусе «Новая» или «В работе».
Сводка учитывает все доступные пользователю заявки,
независимо от фильтров таблицы.

## Структура проекта

- accounts/ — модель пользователя, роли и административная панель.
- tickets/models.py — оборудование, категории, заявки, история и комментарии.
- tickets/forms.py — формы создания, комментариев и фильтров.
- tickets/views.py — обработка запросов и ограничение доступа.
- tickets/services.py — правила переходов статусов и транзакции.
- tickets/tests.py — автоматические проверки.
- templates/ — HTML-шаблоны.
- config/ — настройки проекта и основные маршруты.


## Проверки

Тесты проверяют:
- разграничение доступа;
- создание заявок и защиту от подмены полей;
- допустимые переходы статусов;
- откат изменения статуса при ошибке записи истории;
- комментарии, валидацию и HTML-экранирование;
- поиск, фильтры, сводку и пагинацию.

## Известные ограничения

- На SQLite поиск по кириллице может зависеть от регистра.
- Конкурентные запросы не покрыты текущими тестами.
- История защищена от редактирования через админку,
  но не является неизменяемым журналом аудита.
- Регистрация пользователей пока выполняется администратором.
